# 0.2 -> 0.3 遗留：评测口径两处不对等
0.2 期发现但不改（跑分前已冻结口径，事后改尺子则结论不可信），登记 0.3 处理。
## 缺陷
1. **基线与模型的机会数不同**：`hintOnlyTop1`（`metrics.ts:141-145`）用 `.some()` 遍历所有事件，k 段各算一次；模型 `top1`（`metrics.ts:130-135`）只取 `slice(0,1)` 首段一条。
2. **多事件 Top1 由事件顺序决定**：标注根因落在第二段时该 case 的 Top1 恒假，与模型质量无关；`CaseScore` 未暴露该字段，报告层不可见（JSON 有、schema 无）。
## 修正方向
逐事件判定、全部命中才算该 case 命中；hintOnly 与模型共用同一套 k 段比对。
## 实测影响（0.2 test 集 A 组，分母 14 有标注例）
- 模型 Top1 12/14 = 85.7%；朴素基线 11/14 = 78.6%；**规则组（同集，RULE_FALLBACK）13/14 = 92.9%**
- 规则引擎在每一例上都不弱于模型（模型漏 test-01 / test-08，规则只漏 test-08）：未观测到模型相对规则的增益
- 逐例：都对 10 · 仅模型对 2（test-02 / test-14）· 仅基线对 1（test-01）· 都错 1（test-08）
- test-07 / test-16 为门禁拒答（abstained），不进上述两个分母
## 结论
- 相对朴素基线净增益 1 例（test-02 / test-14），相对规则引擎为 -1 例：**本集测不出模型优于规则引擎**。
- test-02 / test-14 不是模型独有增量：规则引擎靠 `fallback.ts` 的 `beforeFirstAlert` 排序同样答对。
- test-01 是模型唯一输给两个基线的用例，单列跟踪，不得并入「仅模型对」。
- 两处缺陷只会高估朴素基线、不会虚报模型分数；A/C 两组同等受影响，对比仍公平。
